
# Sisyphus API

Backend API for Sisyphus, a Latin vocabulary learning application.

The API handles authentication, user accounts, vocabulary learning, Leitner-style reviews, difficult words, leaderboards, and application data.

## Tech stack

* Python 3.13
* FastAPI
* SQLAlchemy
* PostgreSQL
* Pydantic
* Docker
* pytest
* GitHub Actions

## Features

* User registration and authentication
* Email verification
* Password authentication
* Password reset
* Google OAuth
* Apple Sign In
* Access and refresh tokens
* Secure cookie handling
* User settings
* Latin vocabulary management
* Leitner-style vocabulary reviews
* Difficult-word reviews
* XP and leaderboard system
* PostgreSQL database
* Automated testing
* Docker deployment

## Running locally

### Requirements

* Python 3.13+
* PostgreSQL
* Docker and Docker Compose

### Environment variables

Create a `.env` file containing the required configuration.

Do not commit `.env` to Git.

An example configuration can be found in `.env.example`.

```env
DATABASE_URL=
JWT_SECRET=
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
APPLE_CLIENT_ID=
```

The actual variables required by the application may differ depending on the enabled services.

### Docker

Build and start the API with:

```bash
docker compose up --build
```

The API is available at:

```text
http://localhost:9000
```

FastAPI's interactive documentation is available at:

```text
http://localhost:9000/docs
```

## Testing

Run the test suite with:

```bash
pytest
```

For more detailed output:

```bash
pytest -v
```

## API

The API follows a REST-style architecture.

Authentication endpoints handle registration, login, email verification, OAuth authentication, token management, and password recovery.

Other endpoints provide access to users, vocabulary, learning progress, difficult words, and leaderboard data.

Interactive API documentation is automatically generated by FastAPI.

## Authentication

Sisyphus uses token-based authentication.

Sensitive authentication data is stored server-side or in secure client storage where appropriate. Passwords are hashed before being stored in the database.

OAuth providers currently include:

* Google
* Apple

OAuth credentials and other secrets are supplied through environment variables and are not stored in the repository.

## Database

The application uses PostgreSQL with SQLAlchemy.

Database configuration is supplied through environment variables.

Database credentials and production data must never be committed to the repository.

## Deployment

The API is containerized using Docker.

Production deployment is automated through GitHub Actions and runs the application on a Linux VPS.

The production environment uses HTTPS and environment-specific secrets that are not stored in the repository.

## Postman

The `postman/` directory contains collections for testing the API.

Do not place real production credentials, access tokens, refresh tokens, passwords, or API keys in Postman collections.

Use placeholder values for credentials that need to be shared with the repository.

## Security

If you discover a security issue, do not publish credentials or exploit details in a public issue.

Contact the project maintainer privately with enough information to reproduce the issue.
